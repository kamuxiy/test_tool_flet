## 1. 设备选择器 UI

### 需求演进
- 原生 SN `Dropdown` → 自定义详细下拉
- 浮层不挤压主页布局；不透明；不与已选设备卡片重叠
- 标题为「项目代号 · 机型」；SN / OTA 分两行；设备类型仅图标（手机 / 平板 / 手表）
- 顶部 ADB 文案前增加泛光状态灯

### 实现要点（`main.py` + `core/adb.py`）

| 项 | 说明 |
|----|------|
| 已选卡片 | 标题 `项目代号 · 机型`；副行 `SN`、`OTA`；类型图标 |
| 浮层列表 | 挂在工具栏 `Stack` 最上层；底色实色 `editor_bg`，`opacity=1`；贴在已选卡片下方约 4px |
| 数据源 | `get_device_brief()`：`getprop` OTA/model/characteristics；`dumpsys engineer --query_indicate_info` 取 PCBA |
| 项目代号 | `parse_pcba_from_indicate()`：PCBA 去空白后第 3–7 位（5 位数字）；取不到则 `-----` |
| ADB 灯 | 绿：正常/多设备；黄：未连接/异常；红：无 ADB 环境 |

### 问题 / 修复
- **半透明错觉**：浮层在普通 Column 里被下方「基本操作」盖住 → 提到 `Stack` 顶层 + 不透明底色
- **代号为空**：与「获取设备信息」同源，改走 engineer `PCBA:` 解析而非仅 getprop

## 2. Scrcpy 原生叠层 + 录屏

### 方案收敛（当日多轮试错后的终态）
早期尝试：主程序内嵌面板 → 独立窗口 + HWND 嵌入 → `screencap` 截图预览（延迟约 682ms/帧）→ 最终定为 **原生 scrcpy 叠层**，并同步宿主窗口拖拽 / 缩放 / 最小化。

### 录屏（`subtools/scrcpy_view.py`）

| 项 | 终态 |
|----|------|
| 方式 | `scrcpy --record` 写本机 mp4（同 Scrcpy-GUI）；OPPO 上 `adb screenrecord` 无写权限不可用 |
| 按钮 | **仅开始 / 停止**（已去掉暂停/继续）；结束后保存 **一个** 视频文件 |
| 收尾 | 停止时先对 scrcpy 窗口 `PostMessage(WM_CLOSE)` 写完 `moov`，再等待退出；`Hide`+`terminate` 会产生无法播放的坏 MP4 |
| 目录 | 默认项目下 `scrcpy_records`（也可经设置页覆盖） |

### 关键决策
- 叠层用原生 H.264 流保证低延迟；录屏与镜像同一 scrcpy 进程 + `--record`
- 默认目录：`Path(__file__).parent.parent / "scrcpy_records"`，运行时优先 `user_prefs.get_output_dir("scrcpy_records")`

## 3. 右侧运行日志跟随

### 问题
- TextField 改 `value` 时外层滚动往往不贴底；流畅性分析等后台线程直接改 UI 导致收尾日志丢失
- 用户上翻后再滚回底部，应恢复跟随

### 修复（`main.py`）

| 机制 | 行为 |
|------|------|
| 控件 | `ListView` + `Text`（内容增高触发 `auto_scroll`） |
| `_output_tail["follow"]` | 默认 `True`：新日志跟最新行 |
| 上翻 | `follow=False`，不抢滚动 |
| 滚回底部 | 再置 `follow=True` 并恢复跟随 |
| 统一入口 | 所有走 `append_lines` 的功能共用 |

另：日志区仅内容滚动、宽度撑满右侧（避免连边框一起滚 / 右侧留白）。

## 4. 流畅性分析（Perfetto）

### UI / 日志（`subtools/perfetto_view.py`）
- 「是否属于滑动」radio 文案：**切换 → 点击**
- 后台回调经 `page.run_task` 回 UI 线程再 `append_lines`（勿把同步函数直接当 coroutine）
- 抓取看到 `TTL:` 后继续读；遇到 `Completed ... iterations` **不提前 break**，保留收尾输出，并补「抓取完成 / 结果文件」等提示

### 解析 Excel 未生成

| 问题 | 修复 |
|------|------|
| 短抓取（如 ~600KB）被「≥1MB」跳过，提示「解析完成但未生成 Excel」 | `is_file_larger_than_1mb` 阈值改为 **≥100KB**（函数名未改） |
| `trace_processor_shell.exe` 依赖 cwd | `bin_path = join(dirname(abspath(__file__)), "trace_processor_shell.exe")` |
| 找不到 xlsx | `_find_generated_xlsx` / 解析前后 `rglob("*.xlsx")` 对比新文件 |

涉及脚本：`perf_all_in_one/解析/systrace_FrameTimeline_Analysis_20260330.py`（打包 lite 副本同步）。

## 7. 打包策略更新

### 问题
此前会留下独立的 `dist\perfetto_worker\`，易被当成第二份交付物。

### 修复（`打包为exe.bat`）
- Worker 输出到 **`build\pw_dist\`**（`--distpath` / `--workpath` 在 `build\`）
- 再 `xcopy` 到 **`dist\test_tool_flet\perfetto_worker\`**
- 若存在旧的 `dist\perfetto_worker`，打包结束时删除

**最终交付物仅：`dist\test_tool_flet\`**（内含主程序 + 内嵌 worker）。
